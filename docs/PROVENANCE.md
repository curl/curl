# Release provenance

`scripts/maketgz` generates `curl-X.Y.Z.intoto.jsonl` beside the four release
archives. One JSON Lines record contains an
[in-toto Statement v1](https://github.com/in-toto/attestation/blob/main/spec/v1/statement.md)
with the [SLSA provenance v1](https://slsa.dev/spec/v1.2/build-provenance)
predicate. Its `subject` list records the names and SHA-256 digests of the
`.tar.gz`, `.tar.bz2`, `.tar.xz` and `.zip` archives.

The release manager signs the statement separately using the same GPG key as
the archives. See [VERIFY.md](VERIFY.md#release-provenance) for verification.
Provenance stays outside the archives so that it can describe their final
digests.

This local provenance targets SLSA Build L1. Higher Build levels add
requirements for hosted and hardened build platforms.

## maketgz v1

The URL of this section identifies the `buildType`. It describes the packaging
performed by `scripts/maketgz` in a configured curl source tree. The script
sets distribution versions, regenerates documentation, runs `make dist`,
normalizes archive metadata and creates the four archive formats.

The `buildDefinition.externalParameters` object records:

| Field | Meaning |
| --- | --- |
| `version` | The version supplied as the first script argument. |
| `mode` | The second argument, or an empty string for normal packaging. |
| `sourceDateEpoch` | Timestamp for generated dates and archive metadata. |

`sourceDateEpoch` is a build input. Optional execution timestamps are omitted
so that repeated packaging with the same inputs and outputs can produce
identical provenance.

`buildDefinition.resolvedDependencies` records the actual checked-out git
commit under the canonical source URI `git+https://github.com/curl/curl`.
The release procedure pushes that commit and its tag before uploading the
archives. A published build from a different repository needs the
corresponding source URI. The version argument can be synthetic: it does not
imply that a matching release tag exists.

`runDetails.byproducts` contains the existing `docs/RELEASE-TOOLS.md` evidence:
its SHA-256 digest, media type and base64-encoded content. This records the
Debian package versions collected for autoconf, automake, libtool, make, perl
and git. Other environment inputs remain the local builder's responsibility.

The script captures source identity before packaging modifies files. It
generates commit-based provenance when its source directory is the actual git
root and there are no staged or unstaged tracked changes. Dirty source trees
and extracted archives still produce release archives, with a warning that
provenance was omitted. An extracted archive beneath another git checkout is
treated as extracted source. The `only` mode updates version headers without
generating provenance.

`scripts/dmaketgz` also supports linked git worktrees by exposing their shared
git metadata to the packaging container through a read-only mount.

## local builder v1

The URL of this section identifies `runDetails.builder.id`. The builder's
trust boundary includes the operator, workstation, installed tools, generated
inputs and any container used to run the packaging process. The statement is
generated by those local tools and authenticated by the release manager's
detached GPG signature.

The source check establishes tracked-file cleanliness. Ignored and generated
inputs and concurrent changes remain within the builder's trust boundary.
Independent [reproducible-release verification](VERIFY.md#reproducible-releases)
can check that the published archives match the tagged source.

The file contains a raw Statement signed with detached GPG. The
[in-toto bundle convention](https://github.com/in-toto/attestation/blob/main/spec/v1/bundle.md)
normally recommends envelope records, often signed using DSSE. Compatibility
with DSSE-oriented verification tools requires appropriate envelope and
signing integration plus an accepted builder identity.

The provenance file and detached signature are published beside the archives
on curl.se and attached to the GitHub release. Scorecard's `Signed-Releases`
check detects a GitHub release asset ending in `.intoto.jsonl`; this presence
check does not validate the statement or establish a SLSA level.
